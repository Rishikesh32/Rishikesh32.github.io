Classical machine learning

Classical machine learning is the toolkit of linear models, decision trees, clustering and, above all, careful evaluation. It still powers most prediction on tabular data, and its habits (clean splits, honest metrics, a healthy fear of leakage) are the same habits that keep LLM systems honest.

In this area

    Every classical ML project runs the same loop. You turn raw records into a feature matrix, fit a model (a supervised one when you have labels, an unsupervised one when you only want structure), measure it on data the model never saw, and then diagnose the gap between training and validation performance. The diagnosis sends you back to the features or the model's capacity. The six lessons below follow that loop, and the evaluation and leakage lessons matter just as much when the "model" is an LLM prompt.

    03.1 · Learning from labels

    Supervised learning

    Supervised learning fits a function to examples that already carry the answer: "square metres, postcode → price" or "email text → spam or not". A numeric target makes the task regression; a category makes it classification. Training nudges the parameters until predictions match the labels.

    Why it matters for AI engineers

    Fraud scores, ticket routing and "should a cheap or an expensive LLM answer this?" classifiers are supervised models. Logistic regression on embeddings is often the fastest strong text-classification baseline, and its vocabulary (loss, regularization, logits, probabilities) is the vocabulary of deep learning.

    Loss plus penalty

    You have a matrix \(X\) (\(n\) rows, \(d\) features) and targets \(y\). Training picks the parameters that minimize the average loss (how wrong one prediction is) plus a penalty for complexity. Every model on this site, LLMs included, is trained this way.

    \[ \hat{\theta} = \arg\min_{\theta} \; \frac{1}{n}\sum_{i=1}^{n} L\big(f(x_i;\theta),\, y_i\big) \; + \; \lambda\, R(\theta) \] \(L\): squared error for regression, log loss for classification. \(R\): a regularizer such as \(\lVert\theta\rVert_2^2\) (ridge) or \(\lVert\theta\rVert_1\) (lasso, which drives many weights to exactly zero).

    Linear regression predicts \(\hat{y} = w \cdot x + b\). Each weight reads directly: with \(w_{\text{sqm}} = 3{,}100\), one extra square metre adds about 3,100 to the price, holding other features fixed.

    Logistic regression: a line plus a sigmoid

    For yes/no targets, compute the same linear score \(z = w \cdot x + b\) (the logit) and squash it with \(\sigma(z) = 1/(1+e^{-z})\) into a probability. The model says "class 1" when \(z > 0\), so the decision boundary is the line \(w \cdot x + b = 0\), with \(w\) pointing perpendicular to it.

    Logistic regression decision boundary Try it

    \(w_1, w_2\) rotate the boundary and \(b\) slides it. Press Fit and watch the weights keep growing after the classes are separated: the shading sharpens as the model grows more confident. That is why logistic regression is trained with an L2 penalty.

    Training minimizes log loss (binary cross-entropy), which punishes confident mistakes far more than hesitant ones:

    The rest of the toolbox

    ModelHow it predictsGood atWatch out for
    Linear / logisticWeighted sum (then sigmoid)Fast, interpretable, embeddingsNeeds scaling; misses curves
    k-nearest neighboursVote of the k closest rowsNo training; similarity searchSlow predictions; high dimensions

    from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss, accuracy_score

X, y = load_breast_cancer(return_X_y=True)          # 569 rows, 30 numeric features
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)

# C is the INVERSE regularization strength: smaller C = stronger L2 penalty
clf = make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=1000))
clf.fit(X_tr, y_tr)

p = clf.predict_proba(X_te)[:, 1]                   # probability of class 1
print("accuracy", accuracy_score(y_te, p > 0.5), " log loss", log_loss(y_te, p))
print("weights", clf[-1].coef_[0][:5])              # one weight per scaled feature
    Key ideas
    • Supervised learning minimizes an average loss on labelled examples plus a regularization penalty.
    • Logistic regression is a linear score passed through a sigmoid; its decision boundary is the hyperplane \(w\cdot x + b = 0\).
    • The length of \(w\) sets confidence; its direction sets the boundary.
    • Ridge shrinks weights, lasso zeroes them out.
    • A linear model on good features or embeddings is the baseline every fancier model must beat.
    Common mistakes
    • Skipping feature scaling before a regularized linear model.
    • Reading coefficients as causal effects, or comparing raw coefficients across different units.
    • Using linear regression for a 0/1 target and getting "probabilities" outside [0, 1].
    • Ignoring the convergence warning: the model never finished fitting.

    03.2 · The tabular workhorse

    Trees & gradient boosting

    A decision tree is a flowchart of yes/no questions learned from data. Each question cuts the feature space with an axis-aligned line, and each leaf predicts the average label of the rows that land in it. One tree is unstable; hundreds of them, averaged or added in sequence, are the most reliable models for spreadsheet-shaped data.

    Why it matters for AI engineers

    Gradient-boosted trees (XGBoost, LightGBM, CatBoost) still beat deep networks on most medium-sized tabular problems and train in seconds. Churn scores, cost predictors and "escalate to a human?" classifiers usually start here.

    How a tree splits

    At each node the algorithm tries every feature and threshold and keeps the split that makes the children purest. For classification the usual measure is Gini impurity, the chance that two random rows from the node disagree; for regression it is the variance of the targets.

    \[ \text{Gini}(S) = 1 - \sum_{k} p_k^2, \qquad \text{gain} = \text{Gini}(S) - \tfrac{|S_L|}{|S|}\text{Gini}(S_L) - \tfrac{|S_R|}{|S|}\text{Gini}(S_R) \] A node with 5 defaults and 5 repaid has Gini 0.5. Splitting it into (4, 1) and (1, 4) gives children with Gini \(1 - 0.8^2 - 0.2^2 = 0.32\), so the gain is 0.18.

    Trees ignore feature scale and capture interactions for free, but predictions are a staircase: a tree cannot extrapolate beyond the targets it saw.

    Forests average, boosting adds

    A random forest trains hundreds of deep trees, each on a bootstrap sample (rows drawn with replacement) and with a random subset of features per split, then averages them. Averaging decorrelated trees cuts variance. Gradient boosting instead adds small trees one at a time, each fitted to the current residuals (more generally, the negative gradient of the loss), and shrinks each by a learning rate \(\nu\): \(F_m = F_{m-1} + \nu\, h_m\).

    Gradient boosting with stumps Try it

    Each tree is a stump (one split). At 0 trees the model is the mean; the dashed line is the model one tree earlier. At learning rate 1.0 the fit starts chasing noise within a few dozen trees, which is why real projects use \(\nu\) of 0.01 to 0.1 and early stopping.

    ModelBias / varianceTuning effortTypical use
    Single treeLow bias, high varianceLowExplainable rule sets
    Random forestVariance cut by averagingLow; defaults are goodRobust baseline, out-of-bag estimate
    Gradient boostingBias cut step by stepMedium; must early-stopBest tabular accuracy, ranking
     
    from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestRegressor, HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

X, y = fetch_california_housing(return_X_y=True)       # 20,640 rows, 8 features
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

rf = RandomForestRegressor(n_estimators=300, n_jobs=-1, oob_score=True, random_state=0).fit(X_tr, y_tr)
print("RF  OOB R^2", round(rf.oob_score_, 3), " MAE", mean_absolute_error(y_te, rf.predict(X_te)))

gbm = HistGradientBoostingRegressor(
    learning_rate=0.05, max_iter=2000, max_leaf_nodes=31,
    early_stopping=True, validation_fraction=0.1, n_iter_no_change=50,  # picks the tree count
    random_state=0).fit(X_tr, y_tr)
print("GBM trees", gbm.n_iter_, " MAE", mean_absolute_error(y_te, gbm.predict(X_te)))
    Key ideas
    • Trees split greedily on the feature and threshold that most increase purity.
    • Random forests reduce variance by averaging decorrelated trees.
    • Gradient boosting reduces bias by adding small trees fitted to residuals, scaled by a learning rate.
    • Trees need no scaling and handle interactions, but cannot extrapolate.
    • Choose the number of boosting rounds with early stopping on held-out data.
    Common mistakes
    • Training thousands of boosting rounds with no early stopping.
    • Using trees to forecast values outside the training range.
    • Trusting impurity-based feature importance; prefer permutation importance or SHAP on validation data.
    • Tuning learning rate and tree count separately; they are coupled.

    03.3 · Structure without labels

    Unsupervised learning

    Unsupervised learning finds structure in data with no labels. Clustering groups similar rows ("these 4,000 tickets fall into about 12 themes"). Dimensionality reduction squeezes many columns into a few that keep most of the information. The algorithm never knows what a group means; naming it is your job.

    Why it matters for AI engineers

    Embeddings made this a daily tool. You cluster user queries to see what people really ask your assistant, deduplicate documents before indexing them for RAG, sample eval sets that cover every cluster, and notice drift when a new cluster of traffic appears.

    k-means: assign, update, repeat

    k-means represents each of \(k\) clusters by its centre (centroid) and minimizes the inertia, the total squared distance from points to their centroid. It alternates two steps that each lower the inertia, so it always converges, but only to a local minimum.

    \[ \min_{\mu_1,\dots,\mu_k} \sum_{i=1}^{n} \min_{j} \lVert x_i - \mu_j \rVert^2 \] Assign step: solve the inner \(\min_j\) with centroids fixed. Update step: set each \(\mu_j\) to the mean of its points.
    k-means, one step at a time Try it

    Press Step and watch the phases alternate. Then try New random start with k = 4: some starts put two centroids in one blob and split another, ending with a worse inertia. k-means++ initialization (spread the starting centroids apart) plus several restarts fixes this. Try k = 3 and 5 too; nothing in the algorithm tells you the data has four blobs.

    Choosing k, choosing an algorithm

    Inertia always falls as k grows, so look for the "elbow" where it flattens, or use the silhouette score (near 1 means tight, well-separated clusters). Then read samples from each cluster: useful beats optimal.

    AlgorithmIdeaNeeds k?Use when
    k-meansNearest centroidYesLarge data, round clusters
    HDBSCANDense regions; sparse points are noiseNoOdd shapes, outliers; popular for embeddings
    AgglomerativeMerge closest clusters into a treeCut anywhereYou want a hierarchy
    Gaussian mixtureSoft membership in GaussiansYesElliptical clusters, probabilities

    Dimensionality reduction

    PCA (principal component analysis) is linear and deterministic: centre the data, take its SVD, keep the top directions. Reducing 768-d sentence embeddings to 50 components typically keeps most of the variance and speeds up clustering. t-SNE and UMAP are nonlinear and built for 2-D pictures: they preserve neighbourhoods, but cluster sizes and distances between clusters on their plots mean little. Use them to look, never to measure.

    from sklearn.datasets import make_blobs
from sklearn.preprocessing import normalize
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

# stand-in for real sentence embeddings: 2,000 vectors of dimension 384
emb, _ = make_blobs(n_samples=2000, centers=6, n_features=384, random_state=0)
emb = normalize(emb)                       # unit length: Euclidean distance tracks cosine

pca = PCA(n_components=50, random_state=0)
Z = pca.fit_transform(emb)
print("variance kept", pca.explained_variance_ratio_.sum())

for k in range(2, 11):
    km = KMeans(n_clusters=k, init="k-means++", n_init=10, random_state=0).fit(Z)
    print(k, round(km.inertia_, 1), round(silhouette_score(Z, km.labels_), 3))
    Key ideas
    • k-means alternates assigning points to the nearest centroid and moving centroids to the mean; it finds a local minimum.
    • Use k-means++ and several restarts; choose k with silhouette, elbow and by reading clusters.
    • HDBSCAN finds odd-shaped clusters and labels outliers as noise without a preset k.
    • PCA is a trustworthy linear compression; t-SNE and UMAP are for looking at neighbourhoods.
    Common mistakes
    • Running k-means on unscaled features, so the biggest-unit column decides every cluster.
    • Reading distances between clusters on a t-SNE or UMAP plot as meaningful.
    • Choosing k by minimizing inertia, which always picks the largest k tried.
    • Treating cluster ids as stable across re-runs; they are arbitrary.

    03.4 · Measuring honestly

    Model evaluation & metrics

    A model is only as good as the evidence that it works on data it has not seen. Evaluation has two halves: the protocol (which rows you hold out, and how) and the metric (which number captures the mistakes you care about). A 95%-accurate spam filter can be useless; a fraud model with 2% precision can be worth millions.

    Why it matters for AI engineers

    LLM evals, retrieval metrics, guardrail classifiers and A/B tests all reuse these ideas. If you can explain why accuracy misleads on imbalanced data, you can explain why "98% of outputs were safe" says nothing on its own.

    The protocol: hold out the right rows

    Training data fits parameters, validation data chooses models and hyperparameters, and the test set is opened once to report a number. k-fold cross-validation rotates the validation fold so every row is scored once by a model that never saw it.

    The confusion matrix and the threshold

    Every binary prediction is a true positive (TP), false positive (FP), false negative (FN) or true negative (TN). Precision asks how many flags were right; recall asks how many positives you caught.

    \[ \text{precision} = \frac{TP}{TP+FP}, \qquad \text{recall} = \frac{TP}{TP+FN}, \qquad F_1 = \frac{2\,\text{precision}\cdot\text{recall}}{\text{precision}+\text{recall}} \]

    A classifier outputs a score and you pick the threshold. Lowering it raises recall and lowers precision. The right setting comes from the cost of each mistake: a cancer screen wants recall, an auto-delete feature wants precision.

    Threshold, confusion matrix and ROC Try it

    Each threshold is one point on the ROC curve (recall against false positive rate). The area under it, ROC-AUC, is the chance a random positive outscores a random negative, and it does not move as you drag: it summarizes all thresholds. When positives are rare (fraud at 0.1%), prefer the precision–recall curve, and if you act on scores as probabilities, check calibration: items scored 0.8 should be positive about 80% of the time.

    Error bars

    With 200 test examples at 85% accuracy, the 95% interval is about ±5 points (\(1.96\sqrt{0.85\cdot 0.15/200} \approx 0.05\)). An "improvement" to 87% is noise. Bootstrap any metric for an interval, and always show a trivial baseline beside it.

    Regression metricReads asNote
    MAETypical error in target unitsRobust to outliers
    RMSEError that punishes big missesMuch larger than MAE means a few huge errors
    MAPEPercentage errorExplodes when targets are near zero
    \(R^2\)Share of variance explained vs predicting the meanCan be negative on test data
     
    import numpy as np
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.metrics import precision_recall_curve, roc_auc_score, average_precision_score

# out-of-fold probabilities: every row scored by a model that never saw it
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
p = cross_val_predict(clf, X, y, cv=cv, method="predict_proba")[:, 1]
print("ROC-AUC", roc_auc_score(y, p), " PR-AUC", average_precision_score(y, p))

# highest threshold that still gives recall >= 0.90
prec, rec, thr = precision_recall_curve(y, p)        # len(thr) == len(prec) - 1
i = np.where(rec[:-1] >= 0.90)[0][-1]
print(f"threshold {thr[i]:.3f}  precision {prec[i]:.3f}  recall {rec[i]:.3f}")

# bootstrap a 95% interval for ROC-AUC
rng = np.random.default_rng(0)
idx = [rng.integers(0, len(y), len(y)) for _ in range(1000)]
aucs = [roc_auc_score(y[j], p[j]) for j in idx if len(np.unique(y[j])) == 2]
print("AUC 95% CI", np.percentile(aucs, [2.5, 97.5]))
    Key ideas
    • Train fits, validation chooses, test reports once; split by group or time when rows are related or ordered.
    • Precision: how many flags were right. Recall: how many positives were caught. The threshold trades one for the other.
    • ROC-AUC measures ranking across all thresholds; PR-AUC is more informative when positives are rare.
    • If you act on probabilities, measure calibration.
    • Every score has an error bar; small test sets cannot separate small improvements.
    Common mistakes
    • Reporting accuracy on imbalanced data without the majority-class baseline.
    • Tuning thresholds or hyperparameters on the test set, then reporting that test score.
    • Random K-fold on time-ordered or grouped data.
    • Declaring a winner from a one-point difference on a few hundred examples.

    03.5 · Generalization

    Bias–variance, overfitting & leakage

    A model can fail on new data in two opposite ways. It can be too simple to capture the pattern (underfitting, high bias), or so flexible that it memorizes noise in the training rows (overfitting, high variance). A third failure looks like success: leakage, where information the model will not have in production sneaks into training, and validation scores are too good to be true.

    Why it matters for AI engineers

    Reading the train–validation gap tells you whether to add data, add capacity or regularize. Leakage is the most common reason a model that "scored 0.97" fails in production, and its LLM-era cousin, benchmark contamination, is why public leaderboard numbers need a second look.

    Error has three parts

    \[ \mathbb{E}\big[(y - \hat f(x))^2\big] = \underbrace{\big(\mathbb{E}[\hat f(x)] - f(x)\big)^2}_{\text{bias}^2} + \underbrace{\mathrm{Var}\big[\hat f(x)\big]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{noise}} \] Expectation over different training sets. Bias: how far the average model is from the truth. Variance: how much the model changes when you retrain on another sample. Noise: the floor no model can beat.
    Polynomial degree: under- vs overfitting Try it

    Degree 0 and 1 miss the curve: both errors are high. Around degree 3 to 5 validation error is lowest. Push towards 14 and the curve threads through every training point while validation error explodes. Now raise the number of training points: the same high degree overfits far less, because more data lowers variance.

    Diagnose, then act

    SymptomDiagnosisTry
    Train and validation error both high, close togetherHigh biasMore capacity, better features, less regularization, train longer
    Train error low, validation error much higherHigh varianceMore data, regularization (L1/L2, dropout), simpler model, early stopping
    Validation score suspiciously highProbably leakageAudit features and the split before celebrating

    Leakage

    Target leakage is a feature computed after the outcome, such as "account closed date" in a churn model. Split leakage puts the same user, patient or near-duplicate on both sides, or validates on the past. Preprocessing leakage fits scalers, imputers or feature selection on all rows before splitting:

    from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, GroupKFold

# LEAKY: selection sees every row, including future validation folds
X_sel = SelectKBest(f_classif, k=20).fit_transform(X, y)
leaky = cross_val_score(LogisticRegression(max_iter=1000), X_sel, y, cv=5)

# CORRECT: every step is refit inside each training fold; same user never on both sides
pipe = make_pipeline(StandardScaler(), SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000))
honest = cross_val_score(pipe, X, y, cv=GroupKFold(n_splits=5), groups=user_id)
print(leaky.mean(), honest.mean())       # on wide, noisy data the gap can be huge
    Key ideas
    • Expected error = bias² + variance + irreducible noise.
    • Both errors high: add capacity or features. Big train–validation gap: add data or regularize.
    • More data reduces variance; it does not fix bias.
    • Leakage makes validation scores lie; split first and fit preprocessing inside the training fold.
    Common mistakes
    • Fitting a scaler, imputer or feature selector on the full dataset before splitting.
    • Keeping features that are only known after the outcome happens.
    • Letting near-duplicate rows or the same user land in both train and test.
    • Adding more data to a model that underfits, and waiting for it to help.

    03.6 · Inputs and knobs

    Feature engineering & tuning

    Models only see numbers. Feature engineering turns raw columns (cities, timestamps, free text, skewed amounts) into numbers that expose the pattern. Hyperparameter tuning then searches the settings you choose before training, such as tree depth or learning rate. On tabular problems, good features usually beat a fancier model.

    Why it matters for AI engineers

    Pretrained embeddings are now the default feature for text and images, but they sit next to ordinary columns (account age, plan, hour of day) that still need encoding. And every training job, from a GBDT to a LoRA fine-tune, has knobs you need to search efficiently without fooling yourself.

    One pipeline, one transform per column type

    Linear models, k-NN and SVMs need scaled numbers; trees do not. Categories become one-hot columns, or for thousands of levels, target encoding (the mean label per category, computed out-of-fold to avoid leakage). Two transforms fix common shape problems:

    Tuning: search the knobs, not the test set

    Hyperparameters are chosen on validation folds, never on the test set. Grid search tries every combination; random search samples the space; Bayesian optimizers (Optuna's TPE, for example) use earlier trials to pick promising next ones. When only one or two knobs really matter, which is common, random search explores many more distinct values of them for the same budget.

    Grid vs random search Try it

    The darker band is where validation score is high, and it depends almost only on the horizontal knob. A 3×3 grid tests just three distinct values of it and can miss the band entirely; nine random trials test nine values. That is the argument of Bergstra and Bengio (2012), and why random or Bayesian search is the default.

    import numpy as np
from scipy.stats import loguniform, randint
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import RandomizedSearchCV

pre = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), ["age", "income"]),
    ("cat", make_pipeline(SimpleImputer(strategy="constant", fill_value="missing"),
                          OneHotEncoder(handle_unknown="ignore", sparse_output=False)), ["city", "plan"]),
])
pipe = Pipeline([("pre", pre), ("gbm", HistGradientBoostingClassifier(random_state=0))])

search = RandomizedSearchCV(pipe, n_iter=40, cv=5, scoring="average_precision", random_state=0,
    param_distributions={
        "gbm__learning_rate": loguniform(1e-2, 3e-1),   # sample on a log scale
        "gbm__max_leaf_nodes": randint(8, 64),
        "gbm__min_samples_leaf": randint(10, 200),
    })
search.fit(df_train, y_train)                         # df_train: a pandas DataFrame
print(search.best_params_, search.best_score_)
    Key ideas
    • Put every transform in a pipeline so it is fitted on training folds only and reused unchanged in production.
    • Scale for linear and distance-based models; trees do not care.
    • One-hot for few categories, out-of-fold target encoding or embeddings for many.
    • Log-transform skewed amounts; sin/cos-encode cyclical values.
    • Prefer random or Bayesian search over grids, sample rates on a log scale, and keep the test set out of tuning.
    Common mistakes
    • Computing target encodings on the full training set, which leaks each row's own label.
    • Tuning on the test set, or reporting the cross-validation score of the best of 200 trials as an unbiased estimate.
    • Searching learning rates on a linear scale, wasting most trials on the largest values.
    • Forgetting handle_unknown="ignore" and crashing on a category first seen in production.
