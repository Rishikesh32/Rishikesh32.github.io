Specializations

LLMs are the common core, but many products also need a second, deeper domain: images, audio, generated media, recommendations, forecasts or decision-making agents. Each field below gets a compact primer covering its core tasks, the architectures that matter, how it plugs into LLM work today, and a roadmap for going further. Pick one or two to go deep on.

In this area

    All six fields run on the same foundation you built in deep learning and transformers: tensors, backpropagation, embeddings, attention and careful evaluation. What changes is the shape of the data (pixels, waveforms, user histories, timestamps, reward signals) and the tricks each community invented for it. Today the fields also feed back into LLM work. Vision encoders give language models eyes, speech models give them ears and a voice, diffusion models turn text into media, recommender retrieval is the ancestor of RAG, and reinforcement learning is how chat models get tuned. Read every primer once for orientation, then choose one or two to study properly.

    15.1 · Seeing

    Computer vision

    To a computer, an image is a grid of numbers: a 224×224 colour photo is a 3×224×224 tensor, about 150,000 values. Vision models turn that grid into answers at three levels of detail, and into embeddings that a language model can read.

    Why it matters for AI engineers

    Screenshots for computer-use agents, scanned invoices, product photos and factory inspection all need vision. You will often choose between a vision-language model (flexible, slower, billed per image token) and a small detector (fast, cheap, precise, fixed classes).

    Three tasks, three kinds of output

    Classification outputs one label per image. Detection outputs boxes, each with a class and a confidence score. Segmentation labels every pixel. Detection is scored by mean average precision (mAP), the area under the precision-recall curve, where a prediction counts only if it overlaps a true box enough.

    IoU and non-maximum suppression

    Intersection over union (IoU) measures that overlap. Ground truth (0,0)–(10,10) and prediction (5,0)–(15,10) share 50 units of area out of 150 covered, so IoU = 0.33. It fails the usual 0.5 threshold despite covering half the object.

    \[ \text{IoU}(A,B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|} \] For axis-aligned boxes the intersection is \(\max(0, \min(x_2) - \max(x_1)) \times \max(0, \min(y_2) - \max(y_1))\).

    Detectors emit many overlapping boxes per object. Non-maximum suppression (NMS) keeps the best-scoring box, deletes every box whose IoU with it exceeds a threshold (often 0.45 to 0.7), and repeats. Too low a threshold merges people standing close together; too high reports one car three times.

    IoU between two boxes Try it

    Drag a box body to move it, or drag its corner handle to resize it. Treat the blue box as ground truth and the orange box as a prediction.

    import numpy as np

def iou(a, b):
    # boxes as [x1, y1, x2, y2]
    ix = max(0.0, min(a[2], b[2]) - max(a[0], b[0]))
    iy = max(0.0, min(a[3], b[3]) - max(a[1], b[1]))
    inter = ix * iy
    area = lambda r: (r[2] - r[0]) * (r[3] - r[1])
    return inter / (area(a) + area(b) - inter)

def nms(boxes, scores, thr=0.5):
    order = np.argsort(scores)[::-1]      # best score first
    keep = []
    while len(order):
        best, rest = order[0], order[1:]
        keep.append(int(best))
        order = np.array([i for i in rest if iou(boxes[best], boxes[i]) <= thr])
    return keep

boxes = np.array([[0, 0, 10, 10], [1, 1, 11, 11], [20, 20, 30, 30]], dtype=float)
print(nms(boxes, np.array([0.9, 0.8, 0.7])))   # [0, 2]: box 1 overlaps box 0 with IoU 0.68
# In real code use torchvision.ops.nms(boxes, scores, iou_threshold)

    From CNNs to ViTs to vision-language models

    CNNs slide small learned filters across the image, from edges up to whole objects. Detectors add a head: one-stage YOLO-family models for real time, two-stage Faster R-CNN for accuracy, and DETR, which needs no NMS.

    The Vision Transformer (ViT) cuts a 224×224 image into 196 patches of 16×16 pixels, projects each patch to a vector, adds position embeddings and a CLS token, and runs a standard transformer encoder. With no built-in locality bias, ViTs need large-scale pretraining.

    CLIP trained image and text encoders on about 400 million captioned images so that matching pairs land close together. Compare an image with "a photo of a {label}" for every label and you get zero-shot classification.

    Vision-language models (VLMs) project a vision encoder's patch outputs into an LLM: a 336×336 image with 14-pixel patches becomes 576 tokens. They excel at documents and open questions but are weaker at counting and exact localisation, so high-volume fixed-class jobs still favour a detector.

    Key ideas
    • Classification answers what, detection answers where (boxes), segmentation answers which pixels.
    • IoU is overlap divided by union; it decides true positives in mAP and which boxes NMS removes.
    • CNNs bake in locality; ViTs treat 16×16 patches as tokens and need large-scale pretraining.
    • CLIP aligns images and text in one embedding space, enabling zero-shot labels and image search.
    • VLMs = vision encoder + projector + LLM; images become hundreds of tokens each.
    Common mistakes
    • Mixing box formats (corner vs centre, pixels vs normalised 0–1) between a model and its evaluation code.
    • Forgetting to apply the same resize and normalisation (ImageNet mean and std) at inference as in training.
    • Using a VLM for high-volume, fixed-class detection where a small detector is 100× cheaper.
    • Random train/test splits when near-duplicate frames from the same video land on both sides.
    Starter roadmap
    1. Train a small CNN on CIFAR-10.
    2. Fine-tune a pretrained ViT on your own 5 classes.
    3. Train a detector and compute mAP@0.5 yourself.
    4. Compare zero-shot CLIP with your fine-tuned model.
    5. Build a VLM document extractor with a 50-page eval set.

    15.2 · Hearing and speaking

    Speech & voice agents

    Sound is air pressure sampled thousands of times per second. Speech recognition (ASR) turns it into text, text-to-speech (TTS) turns text back into audio, and an LLM in between makes a voice agent. The models are now good enough that the hard engineering problem is time.

    Why it matters for AI engineers

    Phone support, meeting transcription, tutors and accessibility tools all run on this stack. Building one means picking sample rates, streaming every stage, deciding when the user has finished talking, and measuring error rates on your own audio.

    From waveform to features

    ASR audio is usually 16 kHz (16,000 samples per second); phone audio is 8 kHz. Most models read a log-mel spectrogram: a 25 ms window slides every 10 ms, each window's frequencies are pooled into 80 or 128 bands spaced like human hearing, and the log is taken. One second becomes 100 columns of 80 numbers.

    Recognition and synthesis

    ASR comes in three families and TTS in two. On both sides the trend matches LLMs: large transformers trained on huge, weakly labelled datasets, with audio turned into tokens.

    ApproachHow it worksStrengthExamples

    Transducer (ASR)audio encoder + small prediction network, emits as audio arriveslow-latency streaming, on-deviceRNN-T, Conformer-Transducer

    Score ASR with word error rate (WER):

    \[ \text{WER} = \frac{S + D + I}{N} \] \(N\) is the number of words in the reference. Because insertions count, WER can exceed 100%. Normalise case, punctuation and numbers before scoring, or you will measure formatting instead of recognition.

    Reference "book a table for two at seven" heard as "book table for to at seven pm" has one deletion, one substitution and one insertion: WER = 3/7 ≈ 43%. Normalise case, punctuation and numbers first, or you measure formatting.

    def wer(ref: str, hyp: str) -> float:
    r, h = ref.lower().split(), hyp.lower().split()
    # d[i][j] = edits to turn r[:i] into h[:j]
    d = [[0] * (len(h) + 1) for _ in range(len(r) + 1)]
    for i in range(len(r) + 1): d[i][0] = i
    for j in range(len(h) + 1): d[0][j] = j
    for i in range(1, len(r) + 1):
        for j in range(1, len(h) + 1):
            sub = d[i-1][j-1] + (r[i-1] != h[j-1])
            d[i][j] = min(sub, d[i-1][j] + 1, d[i][j-1] + 1)
    return d[len(r)][len(h)] / len(r)

print(wer("book a table for two at seven",
          "book table for to at seven pm"))   # 0.428...

    The voice-agent pipeline and its latency budget

    A cascaded agent chains four stages: voice activity detection (VAD) spots speech, ASR transcribes, the LLM replies and may call tools, and TTS speaks. The hardest call is endpointing, deciding the user has finished. Wait for 800 ms of silence and the agent feels sluggish; wait 200 ms and it interrupts people.

    Human turn gaps average about 200 ms, so under roughly 800 ms voice-to-voice feels responsive and past 1.5 s feels broken. Stream every stage, start TTS on the LLM's first sentence, keep prompts cached, and support barge-in: stop speaking when the user interrupts and drop the unspoken text from history.

    Speech-to-speech models handle audio in and out in one model, cutting latency and keeping tone of voice. The cascade stays popular because each stage can be logged, swapped and guarded.

    Key ideas
    • Most ASR models read log-mel spectrograms: about 100 frames per second of 80 or 128 numbers.
    • CTC and transducers stream naturally; encoder-decoders like Whisper are robust but chunk-based.
    • WER = (S + D + I) / N, measured after text normalisation on your own audio.
    • Modern TTS often predicts neural-codec audio tokens with a language model.
    • Voice UX lives or dies on time to first audio; stream every stage and handle barge-in.
    Common mistakes
    • Feeding 8 kHz phone audio to a model trained on 16 kHz without resampling.
    • Measuring total LLM generation time when the user only feels time to first audio.
    • Letting the LLM write markdown, URLs or tables that the TTS then reads aloud literally.
    • Keeping the full planned reply in the conversation history after the user interrupted it.
    Starter roadmap
    1. Plot a log-mel spectrogram of your own voice.
    2. Transcribe 20 recordings with Whisper and compute WER.
    3. Score an open TTS model by running ASR on its output.
    4. Wire VAD, streaming ASR, an LLM and TTS; log every stage.
    5. Add barge-in and get under one second voice-to-voice.

    15.3 · Generating media

    Diffusion & generative media

    Destroying an image is easy: keep adding noise until only static remains. A diffusion model learns to run that film backwards, starting from static and removing predicted noise step by step, steered by your prompt.

    Why it matters for AI engineers

    Image and video generation ships in design tools, marketing pipelines, games and e-commerce. Even through a hosted API you choose steps, guidance scale, seeds, resolution and adapters, and each choice trades quality, prompt adherence, diversity, latency and cost.

    The forward process: adding noise on a schedule

    Pick \(T\) steps (classically 1,000) and a noise schedule \(\beta_t\), the noise added per step. Because Gaussians compose, you can jump from the clean image \(x_0\) to any step in one line:

    \[ x_t = \sqrt{\bar\alpha_t}\, x_0 + \sqrt{1-\bar\alpha_t}\, \varepsilon, \qquad \varepsilon \sim \mathcal{N}(0, I), \qquad \bar\alpha_t = \prod_{s=1}^{t} (1-\beta_s) \] \(\bar\alpha_t\) ("alpha bar") is the share of signal variance left at step \(t\). It starts near 1 and falls to near 0. The signal-to-noise ratio is \(\bar\alpha_t / (1-\bar\alpha_t)\).

    DDPM's linear schedule (\(\beta\) from 0.0001 to 0.02) destroys information fast, so many late steps are wasted on near-static. The cosine schedule degrades the image more evenly. Compare them with the slider.

    Forward noising with a schedule Try it

    The reverse process: learning to denoise

    A network \(\varepsilon_\theta(x_t, t)\) learns to predict the noise inside \(x_t\). Training is plain regression: noise a real image to a random step and minimise the squared error between true and predicted noise. Large current models use a diffusion transformer (DiT) as the network.

    Sampling starts from pure noise and subtracts predicted noise step by step. DDPM needs about 1,000 network calls, modern solvers 20 to 50, distilled models 1 to 4. Flow matching learns near-straight noise-to-data paths and also cuts steps.

    Steering: conditioning and classifier-free guidance

    Prompts enter the denoiser through cross-attention to text embeddings. Classifier-free guidance (CFG) strengthens them. Drop the prompt about 10% of the time in training, so one network learns both predictions; at sampling time, extrapolate from the unconditional prediction toward the conditional one.

    \[ \tilde\varepsilon = \varepsilon_\theta(x_t, t, \varnothing) + w \,\big(\varepsilon_\theta(x_t, t, c) - \varepsilon_\theta(x_t, t, \varnothing)\big) \] A negative prompt replaces \(\varnothing\) with text to steer away from. CFG doubles the network calls per step.

    Latent diffusion and the toolbox

    Latent diffusion runs the chain inside a VAE's compressed space: a 512×512×3 image (786,432 numbers) becomes a 64×64×4 latent (16,384), 48× fewer, decoded once at the end. That is what made Stable Diffusion fit on consumer GPUs. Video models add a time axis to the latent.

    The toolbox around the core: image-to-image ("strength" sets how far up the chain a real image starts), inpainting, ControlNet-style conditioning on edges or pose, and LoRA fine-tunes for a style or subject.

    import torch
import torch.nn.functional as F

T = 1000
betas = torch.linspace(1e-4, 0.02, T)               # linear schedule
alpha_bar = torch.cumprod(1.0 - betas, dim=0)

def train_step(model, x0, cond, opt, p_uncond=0.1):
    b = x0.shape[0]
    t = torch.randint(0, T, (b,), device=x0.device)
    eps = torch.randn_like(x0)
    ab = alpha_bar.to(x0.device)[t].view(b, 1, 1, 1)
    xt = ab.sqrt() * x0 + (1 - ab).sqrt() * eps        # jump straight to step t
    drop = torch.rand(b, device=x0.device) < p_uncond  # learn the unconditional case too
    cond = torch.where(drop.view(b, 1, 1), torch.zeros_like(cond), cond)  # cond: (b, seq, dim)
    loss = F.mse_loss(model(xt, t, cond), eps)          # predict the noise
    opt.zero_grad(); loss.backward(); opt.step()
    return loss.item()

# Using a pretrained pipeline from Hugging Face diffusers:
from diffusers import DiffusionPipeline
pipe = DiffusionPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.float16).to("cuda")
image = pipe("a watercolor fox in the snow", num_inference_steps=30,
             guidance_scale=6.0, generator=torch.Generator("cuda").manual_seed(7)).images[0]
    Key ideas
    • Forward: \(x_t = \sqrt{\bar\alpha_t}x_0 + \sqrt{1-\bar\alpha_t}\varepsilon\); the schedule sets how fast signal fades.
    • Training is regression: predict the added noise with an MSE loss at random steps.
    • Sampling cost is steps × network calls; better solvers and distillation cut 1,000 steps to 1–50.
    • Classifier-free guidance extrapolates from unconditional to conditional predictions; scale trades adherence for diversity.
    • Latent diffusion works in a VAE's compressed space, which is why it is affordable.
    Common mistakes
    • Cranking guidance scale to fix a bad prompt, producing burnt, oversaturated images.
    • Comparing models or prompts without fixing the seed, so you are judging noise.
    • Mixing a schedule or sampler with a checkpoint trained for a different parameterisation.
    • Shipping without content filters and provenance (watermark or metadata) on generated media.
    Starter roadmap
    1. Visualise the forward process on MNIST digits.
    2. Train a tiny DDPM on MNIST and sample from it.
    3. Add class conditioning and CFG, then sweep \(w\).
    4. Compare steps, schedulers and guidance in diffusers on a fixed seed.
    5. Train a LoRA on 20 images of one subject and evaluate it.

    15.4 · Personalization

    Recommender systems

    A recommender has millions of items, one user, ten slots and about 100 ms. It learns from what similar users engaged with and from what the items are like. Scoring every item with a heavy model is impossible, so real systems are a funnel: cheap retrieval, then expensive ranking.

    Why it matters for AI engineers

    Feeds, shopping, ads, music and jobs run on recommenders. The machinery also runs through LLM work: two-tower retrieval is embedding search in RAG, ranking is reranking, and ANN indexes, feature stores and A/B tests matured in recommendation teams.

    From a sparse matrix to user and item vectors

    Interactions form a huge, sparse user × item matrix, mostly implicit feedback (clicks, purchases, watch time). A missing click is not a dislike, since the user may never have seen the item, and top positions get clicks just for being on top.

    Matrix factorization learns a k-dimensional vector per user and per item (k of 32 to 256) whose dot product predicts the signal. Item-item collaborative filtering ("people who bought this also bought") remains a strong, explainable baseline.

    \[ \hat r_{ui} = p_u^{\top} q_i + b_u + b_i + \mu, \qquad \min_{p,q,b} \sum_{(u,i)\in \text{observed}} \big(r_{ui} - \hat r_{ui}\big)^2 + \lambda \big(\lVert p_u\rVert^2 + \lVert q_i\rVert^2\big) \] \(p_u, q_i\): user and item vectors; \(b\): biases; \(\mu\): global mean. Train with SGD or alternating least squares (ALS).

    New users and items have no history, the cold-start problem. Content features (text, image and category embeddings), popularity priors and onboarding questions fill the gap.

    Two-stage architecture: retrieval, then ranking

    Retrieval narrows millions of items to about 1,000. A two-tower model gives users and items separate vectors scored by dot product, so item vectors are precomputed into an approximate nearest-neighbour (ANN) index such as FAISS or HNSW. Training contrasts each positive with the other items in the batch, as CLIP does.

    Ranking scores only those candidates, so it can afford hundreds of features: gradient-boosted trees, DLRM-style networks or transformers over recent actions. It predicts several outcomes (click, long watch, purchase) and blends them. Re-ranking then applies diversity, freshness and business rules.

    Two-tower retrieval in two dimensions Try it

    Bigger dots are popular items, which training tends to give longer vectors. Dot product rewards length; cosine scores direction only.

    import torch
import torch.nn as nn
import torch.nn.functional as F

class Tower(nn.Module):
    def __init__(self, n_ids, n_feats, dim=64):
        super().__init__()
        self.emb = nn.Embedding(n_ids, dim)
        self.mlp = nn.Sequential(nn.Linear(dim + n_feats, 128), nn.ReLU(), nn.Linear(128, dim))

    def forward(self, ids, feats):
        x = torch.cat([self.emb(ids), feats], dim=-1)
        return F.normalize(self.mlp(x), dim=-1)          # unit vectors: dot = cosine

user_tower = Tower(n_ids=1_000_000, n_feats=16)
item_tower = Tower(n_ids=200_000, n_feats=32)

def in_batch_loss(u_ids, u_feats, i_ids, i_feats, temperature=0.05):
    u = user_tower(u_ids, u_feats)                       # (B, d)
    v = item_tower(i_ids, i_feats)                       # (B, d); row i is user i's positive
    logits = u @ v.T / temperature                       # other rows act as negatives
    labels = torch.arange(u.shape[0], device=u.device)
    return F.cross_entropy(logits, labels)

    Evaluating recommenders

    Offline, measure retrieval with recall@K and ranking with NDCG@K, which rewards putting relevant items near the top.

    \[ \text{DCG@}K = \sum_{i=1}^{K} \frac{2^{\text{rel}_i} - 1}{\log_2(i+1)}, \qquad \text{NDCG@}K = \frac{\text{DCG@}K}{\text{IDCG@}K} \] IDCG is the DCG of the perfect ordering, so NDCG lies between 0 and 1. A relevant item at rank 1 counts fully; at rank 3 it counts half.

    Split by time, never randomly, and let an A/B test on retention be the final judge. The model only learns from what it showed, so reserve some traffic for exploration.

    Key ideas
    • Implicit feedback is abundant but biased: no click is not a dislike, and position inflates clicks.
    • Matrix factorization learns user and item vectors whose dot product predicts engagement.
    • Production systems retrieve cheaply (two-tower + ANN), then rank expensively, then re-rank with rules.
    • Two-tower training with in-batch negatives is the same contrastive recipe as CLIP and embedding models for RAG.
    • Split by time offline, and trust A/B tests on retention over offline metric gains.
    Common mistakes
    • Random train/test splits that leak future interactions into training.
    • Optimising click-through alone and getting clickbait that hurts retention.
    • Treating every unclicked impression as a confident negative.
    • Ignoring cold start until launch, when every new item gets zero exposure.
    Starter roadmap
    1. On MovieLens, build popularity and item-item baselines; measure recall@10 on a time split.
    2. Train matrix factorization and compare.
    3. Train a two-tower model and serve top-K from FAISS.
    4. Add a gradient-boosted ranker; measure NDCG@10.
    5. Test LLM-written item descriptions on cold-start items.

    15.5 · Forecasting

    Time series

    A time series is a sequence of measurements in time order: hourly API requests, daily sales, GPU temperature every second. Order carries the information. Tomorrow resembles today, Mondays resemble Mondays, and you can never use the future to explain the past.

    Why it matters for AI engineers

    You will forecast token spend and GPU demand, set alert thresholds on latency metrics and catch cost anomalies. Time series is also where leakage hides best, so its habits (time splits, backtests, naive baselines) sharpen every evaluation you run.

    Anatomy: trend, seasonality and noise

    Most series mix a trend, one or more seasonal cycles with a fixed period (24 hours, 7 days, 12 months) and a residual. The additive form is \(y_t = T_t + S_t + R_t\). If the swing grows with the level the series is multiplicative, and a log makes it additive.

    Classical decomposition: a centred moving average with window equal to the period cancels the cycle and leaves the trend; averaging the detrended values at each cycle position gives the seasonal profile; the rest is residual. Set the window off the period and watch the cycle leak.

    Seasonal decomposition of a synthetic series Try it

    Stationarity, differencing and autocorrelation

    A series is stationary when its mean, variance and autocorrelation stay constant over time. ARIMA-style models assume it, so you remove trend by differencing, remove seasonality by seasonal differencing (\(y_t - y_{t-m}\)) and stabilise variance with a log. The autocorrelation function (ACF) shows the structure that remains.

    The augmented Dickey-Fuller test (null: non-stationary) and the KPSS test (null: stationary) give a formal check.

    Models, from baselines to foundation models

    Start with seasonal naive, the value one period ago; it is embarrassingly hard to beat. Move down the table only when a backtest says the extra complexity pays. Prefer quantile forecasts (P10, P50, P90) when decisions depend on risk: you provision GPUs for the P90.

    Backtesting: the only honest evaluation

    Backtesting replays history: train up to a cutoff, forecast the next h steps, slide the cutoff and repeat. Features may only use information available at the cutoff, so a lag-1 feature is useless for a 7-day-ahead forecast.

    MAE and RMSE are in the series' units; MAPE explodes near zero. MASE divides your error by seasonal naive's in-sample error, so below 1 means you beat the baseline.

    \[ \text{MASE} = \frac{\frac{1}{h}\sum_{t=n+1}^{n+h} |y_t - \hat y_t|}{\frac{1}{n-m}\sum_{t=m+1}^{n} |y_t - y_{t-m}|} \] \(m\) is the season length, \(n\) the training length, \(h\) the horizon. MASE below 1 means you beat seasonal naive. 
    import numpy as np
import pandas as pd
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.model_selection import TimeSeriesSplit
from statsmodels.tsa.seasonal import STL

# two years of daily data with a trend and a weekly cycle
idx = pd.date_range("2024-01-01", periods=730, freq="D")
t = np.arange(730)
rng = np.random.default_rng(0)
y = pd.Series(100 + 0.05 * t + 10 * np.sin(2 * np.pi * t / 7) + rng.normal(0, 3, 730), index=idx)

parts = STL(y, period=7).fit()                 # parts.trend, parts.seasonal, parts.resid

horizon = 7                                    # forecast one week ahead
df = pd.DataFrame({"y": y})
for lag in (7, 14, 21, 28):                    # lags >= horizon: known at forecast time
    df[f"lag{lag}"] = y.shift(lag)
df["dow"] = df.index.dayofweek
df = df.dropna()
X, target = df.drop(columns="y"), df["y"]

for k, (tr, te) in enumerate(TimeSeriesSplit(n_splits=8, test_size=horizon).split(X)):
    model = HistGradientBoostingRegressor().fit(X.iloc[tr], target.iloc[tr])
    mae_model = np.mean(np.abs(model.predict(X.iloc[te]) - target.iloc[te]))
    mae_snaive = np.mean(np.abs(X["lag7"].iloc[te] - target.iloc[te]))  # value 7 days ago
    print(k, round(mae_model, 2), round(mae_snaive, 2))
    Key ideas
    • Decompose into trend + seasonality + residual; a moving average with window = period isolates the trend.
    • Stationarity (constant mean, variance, autocorrelation) is reached by differencing and log transforms.
    • Seasonal naive is the baseline to beat; global gradient-boosted models with lag features are the workhorse.
    • Backtest with rolling origins and features available at the cutoff; never shuffle.
    • Forecast quantiles when decisions depend on risk, such as capacity planning.
    Common mistakes
    • Random K-fold cross-validation on time series, which leaks the future into training.
    • Using lag features shorter than the forecast horizon, or scalers fit on the full series.
    • Reporting MAPE on series with zeros or near-zero values.
    • Skipping the seasonal naive baseline and celebrating a deep model that does not beat it.

    15.6 · Learning from reward

    Reinforcement learning

    Reinforcement learning (RL) learns by trial and error. An agent acts, the environment answers with a new situation and a reward, and the agent adjusts so that total future reward goes up. Nobody labels the right action, and the reward often arrives long after the move that earned it.

    Why it matters for AI engineers

    RL is how chat models are tuned on human preferences (RLHF) and how reasoning models learn from verifiable rewards such as passing tests. Knowing its failure modes, especially reward hacking, helps you design reward signals and read model cards.

    The loop and the Markov decision process

    A Markov decision process (MDP) has states \(s\), actions \(a\), transition probabilities, rewards \(r\) and a discount \(\gamma\) that makes near rewards worth more. A policy \(\pi(a \mid s)\) chooses actions to maximise the expected return \(G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots\)

    Value-based learning: Q-learning

    The Q-value \(Q(s,a)\) is the expected return from taking action \(a\) in state \(s\) and acting well afterwards. Q-learning nudges each estimate toward a one-step target: the reward plus the discounted best value of the next state.

    \[ Q(s,a) \leftarrow Q(s,a) + \alpha \Big[\, r + \gamma \max_{a'} Q(s', a') - Q(s,a) \Big] \] \(\alpha\) is the learning rate; the bracket is the temporal-difference error, the surprise between target and current estimate.

    ε-greedy exploration takes a random action with probability ε and the best-known one otherwise. In the gridworld, watch value spread backward from the goal. DQN replaced the table with a neural network to play Atari from pixels.

    Q-learning gridworld Try it 

    import numpy as np
import gymnasium as gym

env = gym.make("FrozenLake-v1", is_slippery=False)    # 4x4 grid, reward 1 at the goal
Q = np.zeros((env.observation_space.n, env.action_space.n))
alpha, gamma, eps = 0.1, 0.99, 0.1
rng = np.random.default_rng(0)

for episode in range(2000):
    s, _ = env.reset()
    done = False
    while not done:
        if rng.random() < eps:
            a = env.action_space.sample()
        else:                                             # greedy, ties broken at random
            a = int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
        s2, r, terminated, truncated, _ = env.step(a)
        target = r + gamma * np.max(Q[s2]) * (not terminated)  # no future after the end
        Q[s, a] += alpha * (target - Q[s, a])
        s, done = s2, terminated or truncated

print(np.argmax(Q, axis=1).reshape(4, 4))                 # greedy action per cell

    Policy gradients and RL for LLMs

    Policy-gradient methods skip the value table and adjust the policy directly: raise the log-probability of actions that did better than expected. "Better than expected" is the advantage \(A\). PPO clips each update so that one batch cannot move the policy too far.

    \[ \nabla_\theta J(\theta) = \mathbb{E}\big[\, \nabla_\theta \log \pi_\theta(a \mid s)\; A(s,a) \,\big] \] Positive advantage pushes the action's probability up, negative pushes it down. Subtracting a baseline from the return reduces variance without biasing the gradient.

    For an LLM, the state is the prompt plus tokens so far, an action is the next token, and the reward arrives when the answer ends. RLHF scores answers with a reward model trained on human preferences, optimises with PPO, and adds a KL penalty to stay near the starting model. GRPO uses each sampled answer's reward minus its group's mean as the advantage, so it needs no value network.

    Verifiable rewards, such as passing unit tests, power reasoning models. The classic failure is reward hacking: scoring high without doing the task, such as padding answers because the reward model likes length.

    Key ideas
    • An MDP has states, actions, transitions, rewards and a discount; the policy maximises expected discounted return.
    • Q-learning moves \(Q(s,a)\) toward \(r + \gamma \max Q(s',\cdot)\); value flows backward from rewards.
    • Exploration (ε-greedy and friends) is required because the agent only learns about actions it tries.
    • Policy gradients push up log-probabilities of actions with positive advantage; PPO keeps steps small.
    • RLHF and GRPO apply the same ideas to LLMs, with reward models or verifiers and a KL leash.
    Common mistakes
    • Bootstrapping from the next state after a terminal step, which leaks value past the end of an episode.
    • Writing a reward that is easy to game, then trusting the reward curve instead of reading outputs.
    • Dropping the KL penalty in LLM RL and watching the model drift into gibberish that the reward model likes.
    • Judging an RL run from one seed; results vary a lot between seeds.
