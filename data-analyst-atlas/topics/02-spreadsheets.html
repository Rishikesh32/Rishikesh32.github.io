Spreadsheets

Excel and Google Sheets are where most analysis starts and where most reports end up. This area teaches you to use them like an analyst: formulas that copy correctly, lookups that join tables, pivots that summarize in seconds, clean inputs, honest charts and models you can question.

In this area

    A typical spreadsheet job follows one path. A raw export arrives, you clean it, enrich it with lookups from other tables, compute new columns with formulas, summarize with a pivot, picture the result in a chart and, when someone asks "what if?", wrap the numbers in a small model. The six lessons follow that path, using one running example: the order export of a small online store that sells mugs, apparel and prints.

    02.1 · How cells compute

    Formulas & references

    A formula is a recipe that points at other cells. Type =B2*C2 once, drag it down 4,000 rows, and every row computes its own revenue. That drag only works because the spreadsheet rewrites each reference as it copies, and the dollar signs you add decide which parts it may rewrite.

    Why it matters for analysts

    Most spreadsheet errors that reach a manager are reference errors: a tax rate that drifted to an empty cell, a total that stops three rows short. If you can read $A2 and A$2 at a glance, you can write a formula once and trust every copy of it.

    Relative and absolute references

    A plain reference like A2 is relative. The spreadsheet stores it as "two columns left, same row", so copying it one row down turns it into A3. That is exactly what you want for per-row inputs such as units and price.

    A tax rate or exchange rate lives in one cell. Lock it with dollar signs, $F$1, and it becomes absolute: every copy points at the same cell.

    Mixed references for two-way tables

    A dollar sign locks only the part that follows it. $A2 locks the column and lets the row move; A$1 locks the row and lets the column move. You need these mixed references whenever one formula fills a grid in both directions, such as units down the side times prices across the top.

    Units run down column A and unit prices across row 1. The formula in B2 is copied to all twelve cells. Toggle the dollar signs and watch which references each copy points at: green cells hold the right units × price, red cells picked up the wrong neighbours.

    Functions, order and errors

    Formulas follow the usual order of operations: brackets, then ^, then * and /, then + and -. So =A2*B2*1+F1 adds the raw tax rate instead of applying it. Functions such as SUM, ROUND, IF and SUMIFS take ranges like B2:B500. When something breaks, the error code tells you where to look.

    ' Row 2 of an orders table: A = units, B = unit price, F1 = tax rate
=A2*B2                     ' revenue, relative: becomes A3*B3 on the next row
=A2*B2*(1+$F$1)            ' revenue incl. tax, tax cell locked
=ROUND(A2*B2*(1+$F$1), 2)  ' round to cents for display and totals
=IF(A2=0, "", B2/A2)       ' avoid #DIV/0! on empty rows
=SUMIFS($C:$C, $D:$D, "North", $E:$E, ">=2026-01-01")  ' conditional total
=$A2*B$1                   ' mixed: fills a units x price grid in both directions
    ErrorWhat it meansUsual cause
    #DIV/0!Division by zero or by an empty cellA rate or average on a blank row
    #VALUE!Wrong type of inputText such as "1,200 " used in arithmetic
    #REF!The referenced cell no longer existsA row or column was deleted under the formula
    #NAME?Unknown function or nameA typo, or a function your version does not have
    #N/AA lookup found no matchA missing key or a stray space (lesson 02.2)
    Key ideas
    • Relative references move with the formula; absolute references ($F$1) stay put.
    • A dollar sign locks only the column letter or row number that follows it.
    • A two-way table needs mixed references: =$A2*B$1.
    • Put constants such as rates in their own labelled cell, never inside formulas.
    • Error codes are clues: #REF! means a deleted cell, #VALUE! means text in arithmetic.
    Common mistakes
    • Forgetting to lock a rate cell, so row 3 multiplies by an empty F2 and silently returns 0.
    • Hard-coding numbers such as *1.08 into formulas, so nobody can see or change the assumption.
    • Totals like =SUM(C2:C500) that stop short when new rows are added. Use a Table (Ctrl+T) or a whole-column range.
    • Typing over one formula cell with a number, which breaks the pattern without any warning.
    In practice

    Press Ctrl+` in Excel (or View › Show formulas in Sheets) to see every formula at once. An inconsistent cell in a column of identical formulas stands out immediately.

    02.2 · Joining tables in a sheet

    Lookups (XLOOKUP & INDEX/MATCH)

    Your orders tab has a SKU on every row, but the product name, category and list price live in a separate products tab. A lookup fetches them: for each order, find the SKU in the products table and bring back the matching value. It is the spreadsheet version of a SQL join, done one cell at a time.

    Why it matters for analysts

    Almost every report combines two tables: orders with products, tickets with agents, campaigns with spend. Lookups are how you do that in a sheet, and a wrong lookup quietly attaches the wrong price to thousands of rows. Knowing how each function matches is what keeps the join honest.

    How a lookup works: find, then return

    Every lookup does two things. It searches a lookup array (the SKU column) for your value and notes the position of the first match. Then it returns the item at that same position from a return array (the price column). XLOOKUP does both in one function; INDEX/MATCH splits them into two.

    XLOOKUP, INDEX/MATCH and VLOOKUP

    XLOOKUP (Excel 2021 and Microsoft 365, and Google Sheets) is the modern default: exact match unless told otherwise, a built-in "not found" value, and it can look left. INDEX(return, MATCH(value, lookup, 0)) does the same job in every version. VLOOKUP still fills old workbooks, but it identifies the return column by a typed number, and that number does not move when the table changes.

    Try a lowercase key (p-103), a key with a trailing space (P-103 ) and a SKU that does not exist. Then insert the Supplier column and compare the three functions.

    Lookup explorer Try it

    When lookups fail

    #N/A means "no match", and the cause is usually the data, not the formula: a trailing space, a SKU stored as a number in one table and as text in the other, or a genuinely new product. Lookups in Excel and Sheets ignore letter case, so p-103 matches P-103, but they never ignore spaces. Approximate match is for ranges such as discount tiers, where you want the largest threshold that does not exceed the value.

    ' Orders tab: B2 = SKU. Products tab: A = SKU, B = Product, C = Category, D = Price
=XLOOKUP(B2, Products!A:A, Products!D:D, "Not found")      ' exact match by default
=INDEX(Products!D:D, MATCH(B2, Products!A:A, 0))            ' 0 = exact match
=VLOOKUP(B2, Products!A:D, 4, FALSE)                        ' FALSE = exact; omit it and you get approximate
=XLOOKUP(TRIM(B2), Products!A:A, Products!D:D, "Not found") ' strip stray spaces first

' Approximate match: discount tier for an order value in E2 (tier table sorted by Min)
=XLOOKUP(E2, Tiers!A:A, Tiers!B:B, 0, -1)                   ' -1 = exact or next smaller
=COUNTIF(Products!A:A, B2)                                   ' 0 means the SKU is missing, 2+ means duplicates
    FunctionDefault matchSurvives inserted columnsNot-found handling
    XLOOKUPExactYesBuilt-in 4th argument
    INDEX/MATCHWhatever you pass to MATCH (use 0)YesWrap in IFNA
    VLOOKUPApproximate if the last argument is omittedNo, the column number is typedWrap in IFNA
    Key ideas
    • A lookup finds a position in one column and returns the same position from another.
    • Prefer XLOOKUP, or INDEX/MATCH where XLOOKUP is not available.
    • VLOOKUP without FALSE does an approximate match and can return a wrong value with no error.
    • Every #N/A is a data question: missing key, stray space or mismatched type.
    • A lookup returns the first match only, so check the lookup table for duplicate keys.
    Common mistakes
    • Wrapping every lookup in IFERROR(…, 0), which turns missing products into zero revenue that nobody notices.
    • Leaving VLOOKUP's last argument out and getting approximate matches on unsorted IDs.
    • Looking up a number against text ("1042" vs 1042): they look identical and never match.
    • Duplicate keys in the lookup table, so the second product's price is never used.

    02.3 · Summarize in seconds

    Pivot tables

    A pivot table groups rows and aggregates them without a single formula. You drop Region into Rows, Month into Columns and Revenue into Values, and 5,000 order lines become a 4 × 12 grid of totals. Under the hood it is a GROUP BY query with a drag-and-drop interface.

    Why it matters for analysts

    "Revenue by region by month", "tickets per agent per week", "average order value by channel": most ad-hoc questions are group-and-aggregate questions. A pivot answers them in under a minute, and it is the fastest way to sanity-check a dataset before you build anything bigger.

    From flat rows to a grid

    The source must be a flat table: one row per order, one column per field, a header on every column. The pivot splits rows into groups by the Rows field, splits again by the Columns field, and runs one aggregation per cell. It adds grand totals on both edges for free.

    Four drop zones, one query

    The field list has four zones. Each maps to part of a SQL query, which is a useful way to check that you asked the question you meant.

    The twelve cards are the source orders, coloured by the field in Rows. Change the zones and watch the same rows regroup. The readout shows the SQL your pivot is running.

    Pivot builder Try it

    Pick the right aggregation

    Sum is the default for numbers, but it is not always the question. Average order value needs Average, "how many orders" needs Count, and "how many customers" needs a distinct count, which in Excel means ticking "Add this data to the Data Model" when you create the pivot.

    -- The pivot "Rows: region, Columns: month, Values: Sum of revenue" as SQL
SELECT region,
       SUM(CASE WHEN month = 'Jan' THEN revenue END) AS jan,
       SUM(CASE WHEN month = 'Feb' THEN revenue END) AS feb,
       SUM(revenue)                                  AS total
FROM orders
GROUP BY region
ORDER BY region;
    ' The same single cell (North, Jan) as a formula, useful for fixed report layouts
=SUMIFS(Orders[Revenue], Orders[Region], "North", Orders[Month], "Jan")
' Average order value per region without a pivot
=AVERAGEIFS(Orders[Revenue], Orders[Region], A2)
    QuestionValues fieldAggregation
    How much did we sell?RevenueSum
    How many orders?Order IDCount
    What does a typical order look like?RevenueAverage (check the median too)
    How many customers bought?Customer IDDistinct count (Data Model)
    Key ideas
    • A pivot is GROUP BY plus an aggregate, with an optional second grouping spread across columns.
    • The source must be flat: one row per record, one header per column, no blank rows or subtotals.
    • Choose the aggregation from the question: sum, count, average or distinct count.
    • Pivots do not update on their own: refresh after the source changes.
    Common mistakes
    • Forgetting to refresh, then presenting last week's numbers.
    • A source range of A1:F500 that misses new rows. Format the source as a Table so the range grows.
    • Averaging an average: a pivot of "average revenue" over pre-averaged rows weights small groups like big ones.
    • Leaving subtotal rows inside the source data, so every total is counted twice.

    02.4 · Tidy before you sum

    Cleaning data in sheets

    Exports from shop platforms, CRMs and survey tools arrive with stray spaces, inconsistent capitals, two fields jammed into one column and numbers stored as text. None of that shows on screen, yet every pivot, lookup and total downstream depends on it. Cleaning is a sequence of small, visible formula steps applied to a copy of the raw data.

    Why it matters for analysts

    A region typed as "North " with a trailing space becomes its own row in a pivot, and a revenue column stored as text sums to zero. Analysts often spend more time cleaning than analysing, so doing it with repeatable formulas instead of manual edits saves hours every month.

    One cell, step by step

    Build each fix as a helper column so you can see what changed. TEXTSPLIT (Excel 365) or SPLIT (Sheets) breaks "name, city" at the comma. TRIM removes leading and trailing spaces and collapses double spaces inside. PROPER capitalizes each word, while UPPER and LOWER force one case.

    Why invisible differences matter

    To a pivot or a lookup, "North" and "North " are different values. A few hundred rows with a trailing space or a typo split one region into several, and each piece looks plausible on its own. Clean the key columns before you group or join on them.

    Six rows from a customer export, with every space that would break matching shown as a dot. Steps run in the order listed. Watch the distinct-city count and the total: SUM skips numbers stored as text, so the total stays at zero until step 4.

    Cleaning stepper Try it

    Numbers, dates and duplicates

    A number stored as text is left-aligned and often shows a small green triangle in Excel. Convert it with VALUE after stripping symbols with SUBSTITUTE. Dates that arrive as text need DATEVALUE or DATE built from pieces. Remove duplicates only after cleaning, otherwise "jane smith" and "Jane Smith" survive as two customers.

    ' A2 = "  jane SMITH ,  london ", B2 = "$1,200" (text)
=TRIM(A2)                                           ' "jane SMITH , london"
=PROPER(TRIM(INDEX(TEXTSPLIT(A2, ","), 1)))         ' "Jane Smith"  (Excel 365)
=PROPER(TRIM(INDEX(SPLIT(A2, ","), 1, 2)))          ' "London"      (Google Sheets)
=TRIM(TEXTBEFORE(A2, ","))                          ' first part, Excel 365
=VALUE(SUBSTITUTE(SUBSTITUTE(B2, "$", ""), ",", "")) ' 1200 as a real number
=TRIM(SUBSTITUTE(A2, CHAR(160), " "))               ' non-breaking spaces from web pages
=UNIQUE(C2:C500)                                    ' list the distinct cleaned values
=COUNTIF(C:C, C2) > 1                               ' TRUE on rows whose value repeats
    Key ideas
    • Never edit the raw tab. Clean in helper columns or a second tab so every step can be checked and repeated.
    • TRIM, then fix case, then split or combine, then convert types, then remove duplicates.
    • Invisible differences (spaces, non-breaking spaces, text vs number) break pivots and lookups.
    • Check your work: count distinct values and compare totals before and after.
    Common mistakes
    • Fixing values by hand, so next month's export has the same problems and nobody remembers the fixes.
    • Running Remove Duplicates before trimming, so near-duplicates survive.
    • Trusting PROPER blindly: it turns "McDonald" into "Mcdonald" and "IBM" into "Ibm".
    • TRIM not removing a web page's non-breaking space (character 160). Substitute it first.
    In practice

    For a cleanup you will repeat every month, record the steps once in Power Query (Excel's Data › Get & Transform). Next month you replace the file and click Refresh. The formula approach on this page is the same logic, done by hand.

    02.5 · Picture the table

    Charts in spreadsheets

    A chart answers one question about a table. Before you click Insert › Chart, say the question out loud: is it about change over time, comparing categories, parts of a whole or a relationship between two numbers? The question picks the chart type, and the table layout decides what lands on each axis.

    Why it matters for analysts

    Most stakeholders read your chart, not your table. A line chart of monthly revenue makes a dip obvious in a second, while the same numbers in a pie hide it completely. Choosing well and cleaning up the defaults is the cheapest way to make an analysis land.

    Let the question pick the chart

    Four questions cover most business charts. Time goes left to right on a line. Comparisons use bars sorted by size, starting at zero. Parts of a whole use a pie or a 100% bar, and only with two or three parts. Relationships use a scatter plot with one dot per row.

    Lay out the data so the chart reads it right

    Spreadsheets build a chart from the selected block. By default, the first column becomes the categories on the x-axis and each header in the top row becomes a series in the legend. If months end up in the legend, use Switch Row/Column in Excel or "Switch rows / columns" in the Sheets chart editor.

    The data is six months of example revenue for two channels, web and store, in $k. Each question uses the slice of the table it needs. Try every chart type on every question and read the verdict.

    Chart-type picker Try it

    Strip the defaults

    Default charts carry clutter: gridlines, a legend you could replace with direct labels, a title that names the data instead of the finding. Rename the title to the takeaway ("Web revenue grew 50% while store slipped"), label the series at the line ends, and remove anything that does not help the reader compare.

    Key ideas
    • Choose the chart from the question: time → line, compare → bar, share → pie or 100% bar, relationship → scatter.
    • First column becomes categories, header row becomes series; switch rows and columns if they land wrong.
    • Bars start at zero. Lines may zoom in, but say so.
    • Make the title the finding, and label series directly instead of using a legend.
    Common mistakes
    • A pie with ten slices, where nobody can tell 11% from 13%.
    • A column chart with a truncated axis that makes a 3% difference look like 300%.
    • Charting a range that includes the totals row, so the last bar dwarfs the rest.
    • 3-D effects, which distort the sizes you are asking people to compare.

    02.6 · Model the decision

    What-if analysis & models

    A spreadsheet model turns a few assumptions into an answer: price, cost and demand go in, monthly profit comes out. Once it is built, you can ask "what if?" by changing one input, by laying out a whole table of inputs at once, or by working backwards from the answer you need to the input that produces it.

    Why it matters for analysts

    "Should we raise the price?", "how many customers do we need to break even?", "what if shipping costs go up 10%?" These questions come to analysts constantly. A small, transparent model lets you answer in minutes and show exactly which assumption drives the result.

    Inputs, calculations, outputs

    Keep the three apart. Inputs are typed numbers, coloured so everyone knows they may be changed. Calculations are formulas that only reference inputs or other calculations. Outputs are the few numbers the decision depends on. Never type a number into a calculation cell.

    \[ \text{profit}(p) = (p - c)\,(2000 - 40p) - F \qquad p^{*} = \frac{50 + c}{2} \] \(p\) is price, \(c\) unit cost, \(F\) fixed cost per month. Setting the derivative to zero gives the profit-maximizing price \(p^{*}\): with \(c = 12\) it is $31, and only half of any cost increase is passed on to the price.

    Data tables and Goal Seek

    A data table (Data › What-If Analysis › Data Table in Excel) recalculates the model for a whole column of input values, so you see profit at $20, $25, $30 and beyond at once. Goal Seek runs the model backwards: set profit to $3,000 by changing price, and Excel searches for the price that gets there. Because profit rises and then falls, two prices work, and Goal Seek returns the one nearest your starting value.

    Drag the price and watch the dot ride the curve; the table on the right is a one-variable data table that refreshes with every input. Then set a profit goal and press Goal Seek to see the search home in on a price.

    Key ideas
    • Separate inputs, calculations and outputs, and colour the inputs.
    • A data table shows the output across many input values at once.
    • Goal Seek works backwards from a target to one input, and returns only one of possibly several answers.
    • The model is only as good as its assumptions: say which ones are guesses.
    Common mistakes
    • Hard-coding an assumption inside a formula, where nobody can find or change it.
    • Reporting Goal Seek's answer without noticing a second, better solution on the other side of the peak.
    • Presenting a model's output to the dollar when the demand assumption is a rough guess.
    • Leaving a large data table on automatic calculation, which slows every edit in a big workbook.

    Projects for this area

    Starter

    Clean and summarize a sales export

    Download a public sample sales dataset (or export your own bank transactions). Keep the raw tab untouched, build a cleaned tab with TRIM, PROPER and VALUE, then answer three questions with one pivot table each.

    Intermediate

    A refreshable monthly report

    Build a workbook where you paste a new month's export into one tab and the lookups, pivots and charts update after a refresh. Add a one-line takeaway above each chart and a data-check cell that flags blanks, #N/A values and row-count changes.

    Stretch

    A pricing what-if model

    Model a subscription product with clearly separated inputs, calculations and outputs. Add a two-variable data table for price and churn, three named scenarios, and a Goal Seek answer to "what price breaks even?". Write half a page explaining which assumption matters most.
